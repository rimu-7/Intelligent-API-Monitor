# Security

Scope: the backend in this repository. This project does **not** claim HIPAA compliance; it avoids storing or logging
raw telemetry so that personal data sent by mistake is never persisted.

## Threat model

| Threat                            | Mitigation                                                                                                                                                                                                                                                                                                    | Test                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Credential stuffing / brute force | argon2id (m=19456, t=2, p=1); per-IP (20 / 15 min) and per-email (5 consecutive failures → 15 min block) limits in Redis with in-memory insurance; same error and timing for unknown emails (dummy hash)                                                                                                      | `auth.test.ts` (6th failed login → 429, unknown email throttled too) |
| Token theft                       | 15-minute JWT access token kept in memory by clients; refresh token is random, stored as sha256, httpOnly cookie scoped to `/api/v1/auth`, rotated on every use; reuse of a rotated token revokes the whole family                                                                                            | `auth.test.ts` (rotation, reuse → family revoked, REFRESH_RACE)      |
| Stale privileges                  | `token_version` in the JWT; role change, deactivation and password change bump it, drop the user cache and revoke refresh tokens                                                                                                                                                                              | `auth.test.ts` (demotion and deactivation end sessions)              |
| CSRF                              | refresh cookie `SameSite=Strict` by default; `/auth/refresh` and `/auth/logout` also require an allowlisted `Origin`; every other route uses a Bearer header, never cookies                                                                                                                                   | `auth.test.ts` (missing / evil Origin → 403)                         |
| Cross-origin abuse                | CORS allowlist of exact origins (never `*`, validated at startup); disallowed origins get no CORS headers; `x-ingest-key` is not an allowed browser header                                                                                                                                                    | `contract.test.ts` §3                                                |
| XSS                               | the API returns JSON only; Swagger UI has its own strict CSP and every other route keeps helmet's defaults; clients must render alert text as text (it may come from an LLM); email HTML escapes every value                                                                                                  | `contract.test.ts` §5, `email-templates.test.ts`                     |
| SSRF                              | the simulator URL comes from the environment only; no endpoint fetches a user-supplied URL                                                                                                                                                                                                                    | code review (`simulator.client.ts`)                                  |
| Path traversal                    | static ingestion takes an exact allowlist key built from the directory listing; user input is never joined into a path                                                                                                                                                                                        | `static-sources.test.ts`, `ingestion.test.ts` §12                    |
| Prompt injection                  | `api_name` must match `^[A-Za-z0-9][A-Za-z0-9._-]{0,119}$` (no spaces or punctuation that could form instructions); telemetry is sent as JSON inside `<telemetry>` tags and the system prompt treats it as data; the output guard rejects ungrounded numbers and wrong shapes; the LLM never decides severity | `telemetry-normalizer.test.ts`, `output-guard.test.ts`               |
| Mass assignment                   | strict Zod objects on auth and user bodies (unknown keys → 400); role can only be set by an admin, never on yourself                                                                                                                                                                                          | `auth.test.ts` (`isAdmin` / `role` in bodies rejected)               |
| Privilege escalation              | central deny-by-default permission map; every route must declare `access` (compile-time) and is checked against OpenAPI by contract tests; no role-name comparisons in routes or services; last active admin protected with row locks                                                                         | `rbac.test.ts`, `auth.test.ts`, `contract.test.ts` §1                |
| Denial of service                 | body limit (`MAX_BODY_SIZE`), batch limit (`MAX_BATCH_SIZE`), global 300/min/IP, ingestion 120/min/principal, refresh 60/min/IP, regenerate 10/min/user, SSE caps (5 per user, 500 per instance), password length ≤ 128, LLM timeouts + circuit breakers, simulator stream auto-stop                          | `ingestion.test.ts` §5, `realtime-jobs.test.ts`                      |
| Secrets leakage                   | secrets only from env; `dev-only-` values, demo mode, insecure cookies and plain-http CORS refused in production; pino redacts auth headers, cookies, ingest/internal keys, passwords, tokens and tickets; request bodies are never logged; errors never include stacks or SQL                                | `env.test.ts`, acceptance log grep                                   |
| PHI leakage                       | unknown telemetry fields dropped before persistence or logging; rejected items store field names and messages only; LLM prompts contain only the API name and metrics                                                                                                                                         | `ingestion.test.ts` §6 (`patient_name` appears nowhere)              |
| Replay / double counting          | `Idempotency-Key` (24 h) per route and principal; simulator retries reuse the key                                                                                                                                                                                                                             | `ingestion.test.ts` §11                                              |

## Operational guidance

- Generate secrets with `openssl rand -base64 48` (use URL-safe passwords inside connection URLs).
- Put a TLS-terminating reverse proxy in front of the API and set `TRUST_PROXY=1`; then do not publish the API port
  publicly (otherwise `X-Forwarded-For` could be spoofed to dodge rate limits).
- Keep `COOKIE_SAME_SITE=strict` unless the frontend is on another site (then `none` + `COOKIE_SECURE=true`).
- `npm audit --omit=dev` reports no high or critical findings (last run: 0 vulnerabilities).
